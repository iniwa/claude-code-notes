併用ワークフロー
Codex で意図を作り、Claude Code に渡し、Codex で受け止める。1 タスクの定型ループ。
基本姿勢

要求と設計は Terra / Sol、設計済みのコード実装はまず Sonnet。Spark は低リスクの補助作業に使い、Luna max は Sonnet が usage limit または service availability で利用不能な場合だけ同じ slice を引き継ぐ。実装は docs/handoffs/YYYY-MM-DD-<task>.md を介して小さく順番に進める。

1
Codex で依頼を分類する
変更種別（文言修正 / 既存調整 / 新規 / 設計変更 / ドキュメント）と影響範囲を最初に切り分ける。 
この依頼の変更種別、影響範囲、設計リスク、
Codex で続行するか Claude Code に handoff するかを分類してください。
2
Codex で設計リスクを切る
責務境界、公開 API、永続化、デプロイに触れるかを Codex で確認する。
高リスクなら先に判断を AGENTS.md に追記する。低リスクなら追記不要。
3
Claude Code に渡せる粒度まで絞る
Goal、Files To Inspect、Files To Edit、Constraints、Non Goals、Data Sources、Acceptance Criteria、Verification、Expected Report がそろうまで Codex で詰める。最初の編集までに広い調査が必要なら、調査を別の read-only slice にする。
4
docs/handoffs/YYYY-MM-DD-<task>.md を作る
Codex が handoff ファイルを書き、ユーザーにパスを伝える。
ユーザーは Claude Code にそのパスを渡す。 
@docs/handoffs/2026-05-08-xxx.md を確認し、
このプロジェクトの調整を行ってください。
5
Claude Code が実装・検証・報告する
Sonnet は AGENTS.md、CLAUDE.md、handoff を読み、Files To Edit の中だけで現在の slice を実装・検証する。
範囲外が必要になったら止まって質問する。中断した場合は使える部分成果・部分編集、完了した検証、残作業、再開条件を報告する。
6
Codex が差分をレビューする
handoff 外の変更、不要なパターン追加、検証不足、公開不可情報の混入がないかを確認する。 
以下の Claude Code 報告と差分を、
AGENTS.md と handoff に照らしてレビューしてください。
7
必要な判断を残し、完了 handoff を archive する
今後も守るべき短い制約だけを AGENTS.md に残し、長い背景は docs/decisions/ に置く。
実装、検証、レビュー、必要な follow-up が完了した handoff は docs/handoffs/archive/ へ移す。
