作業判定と分岐
状況ごとに Codex で閉じるか Claude Code に渡すかを切り分ける。

判定マトリクス

状況 Codex でやる Claude Code へ渡す 注意点
文言修正 そのまま編集 明確な反復編集を独立検証可能な slice にできる場合 設計判断は伴わない。AGENTS.md 追記不要。
新規セクション追加 構造と配線の設計を確定する 設計済みのセクションと配線を実装する nav・SECTIONS・index.html プレースホルダの 3 点更新を必ず指示。
複数ファイルの機械的編集 設計、read-only 調査、小さな文書整合性修正 ファイル数ではなく、1 つの独立検証可能な実装 slice として handoff 編集パターンと適用範囲を Constraints に明記する。
設計変更 判断と AGENTS.md 更新は Codex で完結 判断確定後の機械的反映だけ 設計判断と実装を 1 つの handoff に混ぜない。
バグ修正 原因特定を read-only slice として行う 原因と設計が確定した局所修正を実装する handoff には Non Goals に「リファクタしない」を入れる。
テンプレート更新 方針決定と小さな文書整合性修正 方針確定後のテンプレートと参照ページを同じ slice で更新する場合 公開可否を Codex で必ずレビューする。

Codex に残すか Claude Code に渡すか

Codex で続行:
- 要求が曖昧
- 設計意図がまだ決まっていない
- 責務境界が動く可能性がある
- read-only 調査、レビュー、または小さな文書整合性修正

Claude Code に渡す:
- Goal / Files / Constraints / Non Goals / Data Sources / Acceptance Criteria / Verification が明確
- 設計済みのコード実装または機械的編集が中心
- 1 つの独立検証可能な slice に収まる

設計リスクの見方

新しい責務が増えるか
既存 API やデータ構造を変えるか
UI 層とドメイン層の境界を動かすか
永続化、認証、デプロイに触れるか
一時対応が今後の標準になりそうか
他の実装者が同じ判断を再利用しそうか

handoff できる状態

実装者が迷わず編集できるところまで Codex で詰めてから渡す。
Goal、Background、Files To Inspect、Files To Edit、Constraints、Non Goals、Data Sources、Acceptance Criteria、Verification、Expected Report がそろっていない handoff は渡さない。Expected Report には、中断時の使える部分成果・完了した検証・残作業・再開条件も含める。
