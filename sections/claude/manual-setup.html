プロジェクトセットアップ
新規プロジェクトを Claude Code で作業開始する際のチェックリストと手順書。

1. .gitignore の設定

プロジェクトルートに .gitignore を作成し、以下を含める。 
# ===== Claude Code =====
.claude/

# ===== Serena MCP =====
.serena/

# ===== Python =====
__pycache__/
*.pyc
*.pyo
.venv/
venv/
*.egg-info/

# ===== AI/ML モデルファイル（大容量のため必ず除外） =====
*.bin
*.safetensors
*.gguf
*.pt
*.pth
models/
weights/

# ===== ログ・一時ファイル =====
*.log
*.tmp
*.temp
logs/
tmp/

# ===== 機密情報 =====
.env
.env.*
*.pem
*.key
secrets/

# ===== OS / エディタ =====
Thumbs.db
.DS_Store
*.swp
.vscode/
.idea/
注意: .claude/ にはプロジェクト固有の Claude の記憶・タスク・許可設定が入る。.serena/ には Serena が生成したコードインデックスが入る。どちらも個人環境依存のため、リポジトリには含めない。

2. CLAUDE.md の配置

CLAUDE.md は Claude Code がプロジェクトを開いたとき自動的に読み込む指示書。プロジェクトルートに置く。
AGENTS.md は Codex が設計思想や判断理由を引き継ぐための文書。Claude Code に実装を渡す前に、守るべき設計制約や handoff をここに整理しておく。
CLAUDE.md（最小構成）
# CLAUDE.md

## Purpose
- AGENTS.md owns design intent, model selection, handoff policy, and Codex review.
- This file owns Claude Code execution, verification, and reporting rules.

## Start Of Task
- Read AGENTS.md, CLAUDE.md, the supplied handoff, and listed files before editing.
- Treat that handoff or equivalent inline scope as the approved task scope; it may narrow durable rules but may not weaken them.
- Capture git status --short before editing and compare the final status and diff with that baseline.
- Implement only the current independently verifiable slice.
- Subagents are optional and limited to clearly parallel mechanical work within the same files, scope, and constraints.
- If scope or design is unclear, stop and return it to Codex.

## Safety
- Preserve unrelated changes.
- Do not inspect secrets, credentials, or personal data unless strictly necessary for the approved task.
- Do not edit secrets, credentials, local settings, production data, runtime state, or generated artifacts unless the approved task explicitly requires the change.
- Never reproduce secrets, credentials, personal data, or private infrastructure values in prompts, handoffs, reports, or external tools.
- Do not change deployment or external exposure outside the approved scope.

- Do not commit or push unless explicitly requested.

## Verification And Report
- Run the smallest relevant verification that demonstrates the acceptance criteria are met.
- If interrupted, report usable partial results or partial edits, verification completed, remaining scope or work, and the resume condition.
- Report changed files, summary, verification, blocked checks, subagent usage, and design questions.
AGENTS.md は設計・モデル・handoff方針、CLAUDE.md は編集・検証・報告規則に分ける。別の *_ja.md は作らず、プロジェクト固有の事実と必要な短いルールだけを残す。

3. .claudeignore の配置

Claude Code がコンテキストに読み込むファイルの除外設定。.gitignore と独立して動作する。特に ML プロジェクトでモデルファイルを誤って読み込まないために重要。テンプレートは「テンプレート集」を参照。

4. MCP の登録・確認

プロジェクトで使用する MCP サーバーが正しく登録・動作しているか確認する。
  • /config → mcpServers に必要な MCP が登録されているか確認
  • 各 MCP のツールが Claude Code から呼び出せるかテスト
  • 新規 MCP の追加が必要な場合は「MCP セットアップ」を参照

5. Serena のプロジェクトインデックス作成

Serena を使用するプロジェクトでは、Claude Code の CLI 上で自然言語でインデックス作成を指示する。 
「Serena でこのプロジェクトをインデックスしてください」
Claude が Serena の onboarding ツールを呼び出し、自動でプロジェクトインデックスを作成する。

6. 新規プロジェクト チェックリスト

.gitignore 作成（.claude/, .serena/ を含む）
AGENTS.md をプロジェクトルートに配置（Codex 設計継続用）
CLAUDE.md をプロジェクトルートに配置（Claude Code 実装用）
.claudeignore を配置（ML プロジェクトはモデルファイルの除外を確認）
MCP サーバーの登録・動作を確認
Serena のプロジェクトインデックスを作成（CLI で自然言語指示）
Python 環境は uv or venv でセットアップ（conda は原則使わない）
GPU 使用有無を決め、CUDA バージョンと PyTorch ビルドが一致しているか確認
